1. 设计说明与信息架构

1.1 设计原则

  1. VS Code 原生优先：凡 VS Code 已有成熟 UI（命令面板、编辑器、断点、树视图、通知），一律复用原生交互，不自造控件——降低学习成本与维护成本。
  2. SQL Developer 习惯对齐：目标用户从 SQL Developer 迁移而来，功能行为（Ctrl+Enter 执行、结果内直接编辑、延迟行锁、提交/回滚工具栏）向其看齐（见需求文档附录 A 差异登记）。
  3. 主题自适应：所有自绘 UI（网格、表单、DDL 视图）使用 var(--vscode-*) 主题 CSS 变量，深/浅色主题零适配成本；本档线框以深色示意。
  4. 状态可见：连接状态、事务状态（未提交更改数）、只读模式、执行进度在状态栏与工具栏始终可见；破坏性操作（DROP、ROLLBACK 丢弃更改）一律二次确认。

1.2 信息架构

VS Code 工作台 ├─ 活动栏：SQLAdmin 图标 ├─ 侧栏 │ ├─ 连接（TreeView：连接 → schema → 对象类型 → 对象） §3 │ └─ 待提交更改（TreeView：变更集，随网格出现） §5 ├─ 编辑区 │ ├─ SQL 工作台（.sql 文档，绑定会话） §4 │ ├─ 对象详情（表结构/代码/DDL） §7 │ └─ PL/SQL 调试（断点/单步，复用原生 Debug UI） §8 ├─ 面板区（结果） │ ├─ 结果集标签（可多个）+ 网格 §5 │ ├─ 脚本输出 / DBMS_OUTPUT / 执行计划 §4 │ └─ 调试控制台 §8 └─ 状态栏：连接·schema · 事务 ●未提交 · thin/thick · 行数/耗时 §2

区域说明：

  2. 连接树：已保存连接列表 → 展开为 schema → 对象类型（懒加载+计数）→ 对象；绿色 ● 表示已连接；最后一项固定为「新建连接」。对象可拖拽到编辑器插入名称。

  4. 结果面板：随执行出现在编辑器下方。多语句执行生成多个「结果 N」标签；与「脚本输出 / DBMS_OUTPUT / 执行计划」并列。
  5. 结果工具栏：刷新/筛选 + 编辑动作（加行/删行/预览更改/提交/回滚）+ 导出。仅当结果集可定位单表行（含 ROWID）时编辑动作可用，否则整组置灰并悬浮提示原因（F3-10）。
  6. 状态栏：右下区域显示 当前连接·schema、事务徽标（琥珀色「未提交 N 项更改」）、驱动模式（thin/thick）。点击事务徽标=预览更改。

交互说明：
  1. 运行语句（Ctrl+Enter）：按光标位置用语句切分器定位整句；有选区则执行选区原文（不做切分）。PL/SQL 块（BEGIN…END / CREATE PROCEDURE…）识别为一条语句（F2-02，R4）。
  2. 运行脚本（Ctrl+Shift+Enter）：逐句顺序执行，全部结果入「结果 N」标签；汇总入「脚本输出」；遇错可选「继续/中止」（设置项，默认中止并跳到出错语句）。
  3. 执行计划：对当前语句生成预估计划表格（Operation / Rows / Bytes / Cost），只读展示（F2-12）。
  4. 取消：仅长查询出现；调用 connection.break()，完成后通知已取消（F2-05）。
  5. 错误反馈：ORA 错误以编辑器「问题」波浪线 + 行内悬浮呈现，并利用 errorOffset 直接跳到出错位置（F2-07）。
  6. 绑定变量：语句含 :name 时先弹出赋值 QuickPick（类型推断 + 记住上次值）（F2-08）。

交互说明：
  1. 编辑模型：所有修改先进入变更集（不立即执行 DML）；首次修改某行时按 ROWID 执行 SELECT ... FOR UPDATE 锁定该行，锁失败行标红提示（F3-05/07）。
  2. 类型校验：NUMBER 列输入非法字符即红框 + 悬浮提示（Oracle 精度规则）；DATE 支持 YYYY-MM-DD HH24:MI:SS 与会话格式；输入 NULL（不区分大小写）置空。
  3. 只读判定：JOIN/聚合/无 ROWID 的结果标签标注「只读」，编辑组置灰并说明原因（F3-10）。
  4. 单元格查看器（F2）：长文本/JSON（语法着色）/XML/BLOB（十六进制+另存），可编辑、可全屏（F3-04）。
  5. 复制：右键/命令「复制为 INSERT / CSV / Markdown / 带列名行」，作用于选中单元格或行（F3-01）。
  6. 筛选：列头筛选行（= / LIKE / IN / 范围）默认前端过滤已加载数据，可选「转为查询条件重新执行」（F3-02）。

交互说明：
  1. 启动：F5 运行 .vscode/launch.json 中的 "type": "sqladmin-plsql" 配置（选择连接 + 目标程序单元 + 实参）；也可从对象树的过程节点右键「调试」。
  2. 断点：编辑器行首槽点击；适配器将其映射为 (OWNER, 单元名, 类型, 行号)，会话建立后统一验证并回显「已验证/失效」状态。
  3. 变量：标量与复合类型（RECORD/TABLE）树形展开，懒加载子项；悬停源码中的变量显示即时值；标量支持右键「设置值」（S 级）。
  4. 调用栈：点击栈帧切换「当前帧」上下文，编辑器跳转到对应对象源码行（ALL_SOURCE 拉取只读视图）。
  5. 停止/退出：终止目标会话执行并 DETACH；被调试会话上的未提交事务提示处理方式。
  6. 降级形态（R1 预案）：若 DBMS_DEBUG PoC 不达标，此区域替换为「插桩调试」工作流——命令一键把选中块包上 DBMS_OUTPUT 变量打印，输出进调试控制台（F6-10）。

9. 关键交互流程

流程 A · 执行查询 → 浏览 → 导出（F2 / F3-01 / F4）
  1. 用户在工作台按 Ctrl+Enter → 切分器定位语句 → 校验会话（无则弹连接选择）→ connection.execute(resultSet:true)
  2. 首批 500 行 + 元数据返回 → 结果面板新建「结果 N」标签 → 网格虚拟渲染；状态栏显示耗时。
  3. 用户滚动到底 → getRows(500) 追加；用户点击「导出」选择「全部行」→ 取消当前游标，重新流式执行 → writer 分批写文件 → 进度通知（可取消）。
流程 B · 结果内编辑 → 预览 → 提交（F3-05..09）
  1. 用户双击单元格修改值 → 类型校验通过 → 该行首次修改：按 ROWID 执行 SELECT...FOR UPDATE（失败则标红提示）→ 变更集记录 UPDATE。
  2. 用户加行/删行 → 变更集追加 INSERT/DELETE，网格以绿/红呈现。
  3. 用户点击「预览更改」→ 侧栏列出全部待执行 DML（绑定变量+前后值注释），单项可撤销。
  4. 用户点击「提交」→ 确认框 → 同一事务逐条执行 DML → 全部成功 COMMIT / 任一失败 ROLLBACK 并标红冲突项 → 网格刷新受影响行。
流程 C · 调试存储过程（F6）
  1. 用户配置 launch.json（连接 + 单元 + 实参）并打行断点 → F5。
  2. 适配器建立「调试会话」并 ATTACH 目标会话 → 注册断点（验证回显）→ 目标会话开始执行程序。
  3. 断点命中：目标挂起 → GET_RUNTIME_INFO/GET_STACK/GET_VALUE 取回状态 → DAP 事件 stopped → VS Code 高亮当前行、渲染变量与栈。
  4. 用户单步/继续/设值 → DBMS_DEBUG.CONTINUE 对应模式 → 循环直至结束或用户停止 → DETACH → 控制台汇总（含 DBMS_OUTPUT）。
流程 D · 新建连接 → 测试 → 保存（F1）
  1. 侧栏「＋ 新建连接」→ 表单（W-02）→「测试连接」→ 临时连接 → 版本回显/错误码 → 关闭。
  2. 「保存」→ 连接元数据入全局配置；勾选保存密码时密码入 SecretStorage → 树刷新。
  3. 点击连接项 → 建立会话（工作台/网格按需各取独立连接）→ 状态 ● 绿。
