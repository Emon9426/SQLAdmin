1. 引言

1.1 目的与范围

本文档定义 SQLAdmin 的产品需求，并给出基于版权合规开源组件的可行性分析结论。SQLAdmin 是一个 VS Code 插件，目标用户通过它连接 Oracle 数据库完成日常开发工作：增删改查（CRUD）、导出查询结果、在结果网格中直接编辑数据并提交/回滚、浏览数据库对象、调试 PL/SQL 代码，并为 PostgreSQL 支持预留扩展点。

本文档同时作为后续 原型设计文档 与开发排期的输入。功能范围以 SQL Developer 的「日常开发使用集」为对照基线，不覆盖 DBA 运维类能力（备份恢复、性能监控、数据建模/ER 图等）。

1.2 术语表

术语说明
Thin / Thick 模式node-oracledb 的两种运行模式：thin 为纯 JavaScript 实现（默认，免装 Oracle 客户端，支持 Oracle DB 12.1+）；thick 需加载 Oracle Client 库（19+），支持 Oracle DB 11.2+ 及部分高级特性。
ROWIDOracle 行物理地址，用于结果编辑时唯一定位行并生成 UPDATE/DELETE 语句。
延迟行锁编辑某行时才对该行执行 SELECT ... FOR UPDATE（按 ROWID），避免打开数据即长时间持锁——与 SQL Developer 行为对齐。
DBMS_OUTPUTOracle 服务端 PL/SQL 标准输出通道，工作台执行后自动回收显示。
DBMS_METADATAOracle 服务端包，GET_DDL 用于获取对象 DDL。
DBMS_DEBUG / DBMS_DEBUG_JDWPOracle 服务端调试接口：前者为经典 Probe 接口（12.2 起标记弃用但仍保留）；后者为 JDWP（Java Debug Wire Protocol）方式，SQL Developer / Toad 等采用。
DAPDebug Adapter Protocol，VS Code 调试协议；本插件自研 PL/SQL 调试适配器需实现该协议。
工作台（Worksheet）SQLAdmin 中一个 SQL 编辑器标签页，绑定一个数据库会话（连接），拥有独立事务上下文。
变更集（Changeset）结果网格中未提交的单元格修改、新增行、删除行的集合，可预览生成的 DML，随事务 COMMIT/ROLLBACK。

2. 项目背景与目标

2.1 背景与机会

  • SQL Developer 是多数 Oracle 开发者的默认工具，但它基于独立 Java 桌面技术栈，与现代代码工作流（VS Code、Git、AI 辅助编程）割裂。
  • Oracle 官方 VS Code 插件（Oracle.oracledevtools）免费但闭源，功能以连接、SQL 执行、对象浏览、自治库向导为主，未见开放的 PL/SQL 调试能力，且不可定制、不可二次开发。
  • 开源生态缺口：SQLTools（MIT）提供了连接管理框架但无成熟的 Oracle 驱动与数据编辑能力；DBeaver（Apache-2.0）功能完整但是 Java/Eclipse 桌面形态；社区中不存在成熟的 PL/SQL 调试 VS Code 适配器（本次调研结论，见 §3.2）。
  • 关键使能技术已就绪：node-oracledb 6+ 的 thin 模式以 Apache-2.0/UPL-1.0 双许可开源、纯 JavaScript 实现 Oracle 网络协议，用户无需安装 Oracle 客户端即可连接 Oracle 12.1+——这是本插件可行的技术前提。

2.2 产品目标

  1. 让 Oracle 开发者在 VS Code 内完成 SQL Developer 的日常核心工作：查询、结果编辑与提交/回滚、导出、对象浏览、PL/SQL 调试。
  2. 零客户端安装的连接体验（thin 模式），同时保留 thick 模式兼容 11.2+ 老库。
  3. 完全遵循 VS Code 工作台交互惯例（命令面板、快捷键、主题变量），深浅色主题自适应。
  4. 架构上以「驱动抽象 + 方言抽象」预留 PostgreSQL（及未来其他数据库）的接入能力。
  5. 全链路版权合规：不使用任何专有软件代码/资产；所有第三方依赖可商用、可再分发。

2.3 范围外（Out of Scope）

  • DBA 运维功能：备份恢复、AWR/性能报告、表空间管理、RMAN、Data Pump UI。
  • 数据建模 / ER 图 / 正向逆向工程。
  • Oracle NoSQL / MySQL / SQL Server 等其他数据库（仅预留 PostgreSQL）。
  • PL/SQL 单元测试框架集成（utPLSQL）列为可选项（C 级），不在首发范围。

3.2 技术可行性（分层结论）

UI 层（VS Code） TreeView（连接树/对象树）TextEditor + TextMate（SQL/PLSQL 高亮）WebviewPanel（结果网格/单元格查看器）Debug UI（断点/变量/调用栈）StatusBarItem（连接与事务状态）SecretStorage（凭据）
调试层 自研 DAP 适配器（vscode-debugadapter, MIT）DBMS_DEBUG Probe 控制器（方案 A）JDWP 客户端预研（方案 B）
执行与导出层 语句切分器（自研，处理 PL/SQL 块/注释/引号）流式 Resultset（rs.getRows 分批）connection.break() 取消执行CSV/XLSX(exceljs)/JSON/INSERT/HTML writers（流式）
会话与事务层 每工作台独立会话（事务隔离）空闲会话超时回收变更集管理（pending DML）延迟行锁（ROWID + FOR UPDATE）
元数据层 数据字典缓存（ALL_/USER_/DBA_ 视图）DBMS_METADATA.GET_DDL补全元数据索引（表/列/别名解析）
驱动抽象层（IDbDriver） OracleDriver：oracledb thin（默认）/ thick（可选）PostgresDriver：pg（预留，M5 实装）能力位（capabilities）+ 方言（DDL/元数据/分页）
能力技术方案可行性结论
连接 Oraclenode-oracledb thin（默认，免客户端，12.1+）；thick 可选（11.2+）可行（低风险）。thin 模式为纯 JS 实现的 Oracle Net 协议，已在 utPLSQL VS Code 插件等项目中验证。
增删改查执行connection.execute，多条语句自研切分器；DDL/DML/DQL 统一执行器可行（低风险）。切分器需处理 PL/SQL 块嵌套、注释、引号，属已知工程问题。
大结果集execute(..., {resultSet:true}) + getRows(batch) 分批拉取；网格虚拟滚动；导出全程流式可行（低风险）。
取消执行connection.break()可行。仅对进行中的数据库调用有效，UI 需配合可取消进度。
结果内编辑ROWID 定位 + 延迟行锁 + 变更集 → 生成绑定变量 DML → COMMIT/ROLLBACK可行（中风险）。需精细处理并发冲突（ORA-00054 等）与类型校验，行为对标 SQL Developer。
导出CSV/JSON/INSERT/HTML 自研 writer；XLSX 用 exceljs 流式 WorkbookWriter可行（低风险）。
对象浏览数据字典视图 + DBMS_METADATA.GET_DDL；权限自适应（无 DBA_ 权限回退 ALL_/USER_）可行（低风险）。
执行计划EXPLAIN PLAN + DBMS_XPLAN.DISPLAY（预估计划）；v$session/v$sql_plan 实际计划（需权限，S 级）可行。实际计划依赖权限，需降级提示。
PL/SQL 调试方案 A：自研 DAP 适配器驱动 DBMS_DEBUG（Probe：INITIALIZE/ATTACH/SET_BREAKPOINT/CONTINUE/GET_RUNTIME_INFO/GET_VALUE/GET_STACK）；方案 B：实现 Oracle 定制 JDWP 客户端对接 DBMS_DEBUG_JDWP可行但为本项目最高风险项。开源界无现成实现（本次调研确认）；方案 A 的服务端 API 稳定可用（PL/SQL Developer 仍在使用），但自 12.2 标记弃用；方案 B 协议资料有限。策略：M4 先做方案 A 的 PoC（断点/单步/标量变量/调用栈），同步预研方案 B，PoC 不达标则降级交付（见 §3.4 R1）。
PostgreSQL 预留IDbDriver 接口 + pg 驱动（MIT）+ 方言层（pg_catalog 元数据、DDL 获取）可行（低风险）。核心在于前期接口纪律：元数据、DML 生成、分页、DDL 全部走方言层。

3.4 风险登记册

ID风险等级缓解措施
R1PL/SQL 调试复杂度高：DBMS_DEBUG 已标记弃用（12.2+），JDWP 资料有限，且无开源先例高M4 先行 PoC（2 周盒内验证断点/单步/变量）；PoC 不达标则降级交付「日志增强调试」（DBMS_OUTPUT 自动插桩 + utPLSQL 断言），调试完整版顺延；JDWP 路线并行预研
R2thin 模式能力边界：11.2 老库、部分企业认证（Kerberos 等）与高级特性不在覆盖内中提供 thick 模式开关（用户自备 Oracle Client）；文档明示各模式支持矩阵
R3大结果集内存/性能（网格与导出）中默认分批拉取（500 行/批，可配）+ 虚拟滚动 + 流式导出；设置最大预取上限
R4语句切分器边界情况（PL/SQL 块、动态 SQL、注释内分号）中自研状态机切分器 + 系统化语料测试集；提供「仅执行选中」逃生通道
R5凭据安全（连接密码）中仅存 VS Code SecretStorage；连接配置导出时强制脱敏；只读连接选项
R6结果编辑并发冲突（行锁失败 ORA-00054、数据已被他人修改）中延迟行锁缩小锁窗口；提交前变更集预览；冲突行标红并提示重查
R7VS Code API / node-oracledb 版本演进低锁定引擎最低版本（vscode ^1.85+）；依赖升级纳入季度例行
R8团队对 Oracle 内部机制（数据字典、调试接口）经验不足低风险前置：M1 即建立 gvenzl/oracle-free 容器化集成测试环境，持续积累语料

3.5 总体结论

可行，建议立项。连接、CRUD 执行、结果展示与编辑、导出、对象浏览五类核心功能均有 Apache-2.0/MIT/UPL 级别的合规开源基座（核心为 node-oracledb thin 模式），工程上均为成熟模式，风险可控。

唯一的高风险项是 PL/SQL 调试：开源界无现成 DAP 适配器（本报告调研确认），需基于 DBMS_DEBUG（方案 A）自研，并以 JDWP（方案 B）作为演进路线。采用「PoC 先行 + 降级预案」策略后，整体项目风险可接受。

4. 用户角色与典型场景

4.1 用户角色

角色描述核心诉求
后端/ETL 开发工程师（主要）日常写 SQL 与 PL/SQL，从 SQL Developer 迁移而来快速执行、改数据、导数据、调试存储过程
DBA（次要）多套环境巡检、对象核查多连接管理、对象浏览、DDL 核查、只读保护
数据分析师（次要）以查询与导出为主大结果集流畅、导出 Excel、格式友好

4.2 用户故事（User Stories）

编号故事验收要点
US-01作为开发，我能新建 Oracle 连接（仅主机/端口/服务名/账号），测试连通后保存，密码不明文落盘。密码仅存 SecretStorage；settings 导出的连接不含密码
US-02作为开发，我能在工作台执行选中的 SQL，多语句执行时每个结果集一个标签页。Ctrl+Enter 执行当前语句；多结果集按序分标签
US-03作为开发，我能在结果网格中直接改单元格、增删行，预览将执行的 DML，再统一提交或回滚。脏单元格/新增行/删除行有明确视觉标记；提交前可预览 SQL；回滚清空变更集
US-04作为分析，我能把查询结果全量导出为 XLSX/CSV/JSON/INSERT，不受网格已加载行数限制。100 万行级导出为流式、内存有上界、进度可取消
US-05作为开发，我能在对象树中查看表结构、注释、索引、约束与 DDL，并一键打开表数据。DDL 由 DBMS_METADATA 生成；表数据打开进入可编辑网格
US-06作为开发，我能在存储过程里打断点、单步执行、查看变量与调用栈，定位逻辑错误。断点命中即挂起；变量可展开复合类型；调试不影响其他工作台会话
US-07作为 DBA，我能为生产连接开启只读模式，防止误改。只读连接下网格禁用编辑、DML 执行前拦截确认
US-08作为开发，未来团队切换 PostgreSQL 时，插件可平滑加装 pg 支持。驱动接口（IDbDriver）稳定，连接 UI 类型下拉已预留

5. 功能需求

优先级采用 MoSCoW：M 必须 S 应该 C 可以 W 暂缓。

5.1 F1 连接管理

编号需求优先级说明与验收要点
F1-01新建/编辑/删除/复制连接M字段：名称、类型（Oracle；PostgreSQL 预留置灰）、连接模式（基本 / TNS 别名 / 连接串）、主机、端口(默认1521)、服务名/SID、用户名、密码、角色（DEFAULT/SYSDBA/SYSOPER）
F1-02测试连接M表单内一键测试，返回成功/失败与错误码（ORA-xxx）
F1-03保存连接 / 用户名 / 密码M连接配置（主机/别名、端口、角色等）与用户名一并保存于本地；密码可选保存——仅入 VS Code SecretStorage（永不明文写入配置文件），或选择「不保存密码，连接时询问」；连接配置导出强制脱敏
F1-04连接树与状态M侧边栏树展示已保存连接；状态徽标：已连接（绿）/连接中（转圈）/断开/错误；单连接可多会话（每工作台一个）
F1-05本机 tnsnames.ora / TNS 别名M三种寻址模式：基本 / TNS 别名 / 连接串（Easy Connect）。TNS 模式自动定位本机 tnsnames.ora（查找顺序：TNS_ADMIN 环境变量 → %ORACLE_HOME%\network\admin → 手动指定路径），解析并列出全部别名（悬浮显示 HOST/PORT/SERVICE 摘要），支持重新解析；解析失败提示出错行号与原因
F1-06只读连接开关S连接级配置；开启后禁用网格编辑与 DML（US-07）
F1-07thick 模式开关S连接级或全局指定 Oracle Client 路径（11.2+ 兼容，R2）
F1-08连接分组/颜色标签C环境分组（DEV/TEST/PROD）与颜色标识，防误连
F1-09连接配置导入导出CJSON 导出强制脱敏（不含密码）

5.2 F2 SQL 工作台

编号需求优先级说明与验收要点
F2-01新建工作台M命令/连接树右键新建；工作台绑定一个数据库会话；标题显示「连接 · schema」
F2-02执行当前语句（Ctrl+Enter）M依据光标位置切分定位语句；有选区时执行选区原文
F2-03多语句/脚本执行M逐句执行；每个结果集独立标签；脚本输出汇总（每句耗时、影响行数、错误继续/中止选项）
F2-04结果集展示M列头来自元数据；分批拉取+虚拟滚动；NULL 特殊显示；底部行数/耗时/继续获取
F2-05取消执行Sconnection.break()；进度通知可取消
F2-06DBMS_OUTPUT 面板M自动 ENABLE，执行后自动 GET_LINES 回显；缓冲上限可配
F2-07错误定位S利用 errorOffset 将光标跳到出错位置，错误消息悬浮提示
F2-08绑定变量S识别 :name，执行前弹出赋值框（记住上次值，按会话缓存）
F2-09语法高亮与括号/折叠M自研 TextMate 文法（SQL/PLSQL language contribution）
F2-10智能补全S关键字、schema.对象、列（含 JOIN 别名解析）、存储过程签名；元数据异步缓存
F2-11格式化 / 缩进S文档级 Shift+Alt+F、选区级 Ctrl+K Ctrl+F；基于 sql-formatter（plsql 方言）+ 语句切分器 AST：PL/SQL 块感知缩进（BEGIN/END、LOOP、IF/ELSIF、EXCEPTION 逐级缩进）；缩进宽度、空格或 Tab、关键字/标识符大小写、逗号与 AND/OR 对齐均可配置；格式化仅调整空白，不改变语义
F2-12执行计划S预估计划：EXPLAIN PLAN + DBMS_XPLAN.DISPLAY，表格化展示；实际计划（需权限）C 级
F2-13查询历史C按连接记录最近执行语句，可搜索回填
F2-14代码导航与跳转MGo to Definition（F12 / Ctrl+点击）：源码/DDL 中的标识符（表/视图/同义词/序列/过程/函数/包）跳转——表/视图打开结构页，代码对象打开源码（ALL_SOURCE）并定位到行；查找所有引用（Shift+F12，ALL_DEPENDENCIES + 源码扫描）；跳转到行 Ctrl+G（原生）；面包屑显示 Schema › 对象 › 子程序 › 行号；错误位置（F2-07）与调试栈帧（F6-06）跳转复用同一机制

5.3 F3 结果网格与数据编辑

编号需求优先级说明与验收要点
F3-01网格基础能力M列排序（前端）、列宽拖拽/自适应、行多选（Ctrl/Shift）、选中行数统计、单元格复制（含「复制为 INSERT/CSV/Markdown」）
F3-02筛选与查找S列筛选条件行（=、LIKE、IN、范围）；前端过滤已加载数据 + 「重新按条件查询」（后端 WHERE）双模式
F3-03NULL 与特殊类型显示MNULL 斜体灰显（文本可配）；NUMBER/DATE/TIMESTAMP 按 Oracle 精度原样显示；BLOB/CLOB 显示为 (BLOB)/(CLOB) 占位并可查看/另存
F3-04单元格查看器S双击/快捷键打开侧边或弹层：长文本、JSON 着色、XML 着色、十六进制（BLOB）、单行/折行切换、编辑（配合 F3-05）
F3-05单元格编辑与校验M按列类型校验（NUMBER 精度、DATE 格式）；输入 NULL 显式支持；编辑即入变更集（不立即执行）
F3-06行级增删M新增行（网格底部 * 行，录入主键）；删除行支持多选；均入变更集
F3-07延迟行锁M首次修改某行时按 ROWID 执行 SELECT ... FOR UPDATE；锁失败（ORA-00054）标红提示重试/跳过
F3-08变更集与 SQL 预览M侧栏「待提交更改」列表（UPDATE/INSERT/DELETE 分组）；每项可查看绑定变量 SQL；单项可撤销
F3-09提交 / 回滚M工具栏与命令（Ctrl+Alt+C / Ctrl+Alt+R）：仅当变更集非空时按钮可用——可用态高亮+待处理计数徽标，空时置灰（网格工具栏/变更集面板/状态栏三处一致）；提交=变更集 DML 全部执行+COMMIT（原子），失败回滚并报告；回滚与关闭含未提交更改的网格需二次确认；连接错误或带未提交更改断开时默认回滚（服务端会话终止自动回滚未提交事务，UI 通知确认「回滚并丢弃（默认）/ 尝试重连」，重连后原事务已回滚、变更集同步清空）
F3-10编辑能力边界S仅当查询为「单表可定位」（有可用 ROWID）时启用编辑；含 JOIN/聚合/ROWNUM 改写的结果为只读并说明原因
F3-11粘贴批量行C从 Excel/TSV 粘贴多行多列，按列对齐入变更集
F3-12外键/引用完整性提示C编辑违返约束时，错误消息翻译为可读提示（ORA-02291 等）

5.4 F4 导出

编号需求优先级说明与验收要点
F4-01导出格式MCSV、XLSX（exceljs 流式）、JSON、INSERT 语句、HTML 报表
F4-02导出范围M已加载行 / 全部行（重新流式执行）/ 选中行

5.5 F5 数据库对象浏览器

编号需求优先级说明与验收要点
F5-01对象树结构M连接 → 当前 schema（可切换/浏览其他 schema，S 级）→ 对象类型节点（表/视图/物化视图/序列/过程/函数/包/触发器/类型/同义词/DB Link/作业）→ 对象；类型节点懒加载并显示计数
F5-02树搜索过滤M按名称前缀/模糊过滤；支持「仅显示匹配类型」
F5-03表对象详情M标签页：列（名称/类型/可空/默认值/注释）、数据（进入可编辑网格，自动带 ROWID）、约束（主键/外键/唯一/检查，外键可跳转引用表）、索引、触发器、DDL（DBMS_METADATA，带 SQL 着色+复制+另存）、统计信息（行数/大小，S 级）
F5-04代码对象详情M过程/函数/包/触发器/视图/类型/序列：源码（USER_SOURCE/ALL_SOURCE）或 DDL 查看，S 级：跳转定义/引用查找（WHERE name LIKE）
F5-05右键操作集S打开、查看数据、SELECT/INSERT 骨架生成到工作台、重命名、删除（DROP，需确认对话框并显示影响）、刷新、复制名称
F5-06权限自适应S有 DBA 权限时可用 DBA_ 视图浏览全库；否则回退 ALL_/USER_，无权限节点隐藏或置灰
F5-07树刷新与缓存S手动刷新 + 会话内缓存（DDL 变更后可失效）

5.6 F6 PL/SQL 调试（依赖自研 DAP 适配器，M4 交付）

编号需求优先级说明与验收要点
F6-01调试会话建立M选择连接与目标程序单元（过程/函数/包/匿名块）；自动创建「目标会话 + 调试会话」两条数据库连接（同插件进程内）
F6-02行断点M编辑器行首槽点击设置；映射到 (OWNER, 对象名, 类型, 行号)（包体按 body 行号）；断点未验证/已验证/失效状态
F6-03启动/附加与停止MF5 启动调试（目标会话执行程序，断点挂起时 UI 停在该行）；停止=DETACH 并终止目标会话执行
F6-04单步执行M继续 / 单步跳入 / 单步跳过 / 跳出（DBMS_DEBUG.CONTINUE 各模式）
F6-05变量值查看M变量窗格显示全部局部变量当前值（标量 + RECORD/集合等复合类型树形展开、子项懒加载），值随断点挂起/单步自动刷新；悬停源码标识符弹出 DataTip 即时值；右键复制值；标量修值（SET_VALUE）为 S 级
F6-06调用栈M栈帧列表（GET_STACK），点击跳转对应对象源码行
F6-07监视表达式S标量表达式求值（GET_VALUE 语法）
F6-08DBMS_OUTPUT 联动S调试挂起/结束时回收 DBMS_OUTPUT 到调试控制台
F6-09异常断点C未处理异常自动断在抛出位置
F6-10降级预案S若 DBMS_DEBUG PoC 不达标（R1）：交付「插桩调试」——一键在选中 PL/SQL 前后注入 DBMS_OUTPUT 变量打印 + utPLSQL 断言运行；DAP 完整版顺延

6. 非功能需求

维度要求
性能连接建立 ≤2s（局域网）；首屏 500 行 ≤1s；网格 10 万已加载行滚动不掉帧（虚拟滚动）；100 万行导出 XLSX ≤90s 且峰值内存 ≤500MB（流式分批，可取消）
安全密码仅存 SecretStorage；导出的连接配置脱敏；只读模式可拦截 DML/编辑；不内置任何明文凭据默认值；文档提示生产环境用最小权限账号
兼容性VS Code ≥1.85（桌面版；Remote SSH/WSL 场景目标支持，Web 版 vscode.dev 为 C 级）；Windows/macOS/Linux；Oracle DB 12.1–23ai（thin），11.2+（thick，用户自备客户端）；Node 18+
可靠性连接断开自动检测并提示重连；未提交更改保护（关闭前确认）；插件异常不拖垮 VS Code 主进程（崩溃后连接资源由服务端回收）
可维护性TypeScript strict；核心层（驱动/执行/变更集）与 UI 层解耦，核心层单元测试覆盖率 ≥70%；依赖许可证 CI 校验；语义化版本 + CHANGELOG
可扩展性IDbDriver + 方言注册机制；对象类型详情页可插拔（为 PG 及未来库扩展）
可用性所有操作与 SQL Developer 习惯对齐（Ctrl+Enter 执行、结果内直接编辑、F5 调整为脚本执行避免冲突）；深浅色主题自适应；中文/英文
